# Color design system

NexNote uses Material 3 semantic roles throughout the application. Manual themes
are generated by MaterialKolor's `SchemeTonalSpot` from the nine existing accent
seeds. `ColorSchemes.kt` maps the complete role set supported by the current
Compose dependency, including fixed and inverse colors and the surface-container hierarchy.
Do not add per-screen hex palettes or infer dark mode from a surface's luminance.

## Note surfaces

`NOTE_COLOR_PALETTE` in `domain/model/NoteColorPalette.kt` defines the stored
color choices for both the editor and the debug note generator. The generator
cycles through all choices, including the default, and never stores resolved theme
colors. Existing notes retain their stored identities.

`resolveNoteColors` is the single source for note presentation. Stored ARGB values
remain unchanged: they identify the user's selected color, rather than the final
display color. The resolver harmonizes their hue towards the theme primary using
Material's bounded harmonization, caps chroma at 36, and uses tone 94 in light mode
or 24 in dark mode. These tone choices are NexNote design decisions, not mandatory
Material constants. A note without a custom color uses `surfaceContainerLow`.

Contrast is measured on the final opaque sRGB colors. The resolver targets 7:1
for note body text, 4.5:1 for secondary text and links, and 3:1 for outlines.
`NoteContentTheme` scopes text and nested controls to the actual note surface.
Cards in shared collections and trash use the same resolver. The editor uses
one continuous note surface across its top bar, transparent mode
tabs, tags and writing/preview area. Navigation and search remain visible while
tags retain their existing collapse behavior. Locked Vault screens ignore the stored
note color. Nested color selectors resolve against the original application scheme
to avoid applying harmonization twice.
Selection preserves the note's color and adds an indicator/border.

`rememberContentMarkdownColors` supplies identical link and code colors to compact
cards, trash, full previews, and background parser warmup. New Markdown consumers
must use it to preserve both visual consistency and cache-key agreement.

## Device colors and OLED

Device colors are opt-in and default to off. Android 12+ supplies the dynamic
scheme; earlier versions retain the manual palette. Enabling device colors never
overwrites the saved manual accent. The color selectors resolve their
colors from the active scheme, including dynamic themes.

The Black mode applies its OLED override after palette generation. Only the base
surfaces become black; elevated containers retain their hierarchy. Colored notes
remain tonal rather than being blended towards black. Screens using
`nexNoteBackground` add a vertical accent tint in other modes; OLED disables
that gradient.

## Layout and verification

Color selectors expose named, selected semantics and 48 dp touch targets. Settings
choices wrap instead of compressing labels into fixed-width segments. Shared cards
use the theme shapes; persistent navigation and radial actions use opaque surfaces.
Scrolling should not introduce an unrelated surface color.

Follow [Running tests](testing.md) for build and device-test commands.
`ColorContrastTest` covers all manual seeds and display modes, preset colors and
representative imported colors. `DynamicColorSchemeTest` checks the device palette
and manual fallback; `DynamicColorPreferenceTest` checks persistence.
The editor regression test checks that a colored direct preview finishes warming
up after accent changes. `ThemeGalleryTest` renders the 27 manual combinations
for visual inspection; its images are review artifacts, not automatic visual approval.

## Typography and shared components

`Fonts.kt` maps `AppFont` to System, Inter, Lora, Fira Code, or JetBrains Mono.
`buildNexNoteTypography` applies the typeface and text size. Fonts load locally;
see [Asset provenance](fdroid-asset-inventory.md#bundled-fonts) for their licenses.

Note cards share `NoteCardContent`. Compact shows a title, Preview adds body text,
and With information adds date, tags, and files. The legacy value `TITLE_DATE`
maps to `TITLE_INFORMATION`. Untitled notes use a localized placeholder and keep
the first line in the body preview. Settings reuses the card for its live sample.
`TemplatePreviewText` resolves date placeholders and removes empty list markers
from previews without changing saved templates.

Selection uses `SelectionTopAppBar`; per-note actions use `NoteActionsSheet`.
Agenda hides its other controls during selection. Icon actions need localized
labels. Radial actions expose one button node each. Markdown tasks expose checkbox
state and use parser source-line mapping for edits; read-only previews must not
offer checkbox edit actions.
